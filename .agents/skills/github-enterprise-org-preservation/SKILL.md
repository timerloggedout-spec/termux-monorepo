# GitHub Enterprise organization preservation

## Objective

Preserve every repository and operational asset owned by an organization before its Enterprise account reaches a trial-expiry or deletion deadline. Bind each action to the exact source organization, destination, deadline, baseline, and evidence receipt.

## Trigger

Use this skill when GitHub reports:
- an Enterprise trial ending or scheduled for deletion;
- an organization associated with an expiring Enterprise account;
- a requirement to move an organization or its assets to GitHub Free;
- a need to preserve repositories, Actions, integrations, or organization settings before account cleanup.

## Required inputs

- Enterprise account slug and deletion date.
- Source organization slug.
- Authenticated operator identity and owner/admin permissions.
- Destination organization slug and plan, when repository transfer is required.
- Current source inventory and baseline artifact.
- Explicit operator authorization for repository transfer.

## Procedure

### 1. Reconstruct the notice

1. Inspect the original GitHub Support email and any companion organization-trial notice.
2. Record the received date, exact deletion date, Enterprise slug, and every organization named in the notice.
3. Verify the organization-to-enterprise association in GitHub settings.
4. Separate the personal account, adjacent organizations, and unrelated repositories from the affected scope.
5. Classify notice-derived facts as verified evidence and inferred relationships as candidates.

### 2. Reconstruct organization state

1. Read repository instructions, proposal registry, permissions, and the current preservation runbook.
2. Enumerate source repositories with `type=all` and pagination.
3. Capture repository IDs, names, visibility, default branches, sizes, refs, releases, workflows, environments, deployments, Pages flags, and repository-level integration names.
4. Capture organization-level Actions secret names, variable names, webhooks, GitHub App installations, members, teams, projects, and package metadata where supported.
5. Record API permission gaps as UNVERIFIED with the endpoint and HTTP status.
6. Keep secret values, token values, webhook URLs, and private key material outside reports and artifacts.

### 3. Select the preservation path

**Path A — retain the existing organization**

1. Inspect Enterprise → Organizations as an Enterprise owner.
2. Confirm GitHub exposes the Remove organization operation for the source.
3. Review trial-created organization restrictions and the downgrade summary.
4. Execute the owner operation when GitHub confirms the organization becomes independent on GitHub Free.
5. Verify the same organization ID and all baseline assets after removal.

**Path B — transfer repositories to an independent Free organization**

1. Create the destination from personal-account Settings → Organizations → New organization → Choose GitHub Free.
2. Confirm the destination exists outside the expiring Enterprise account.
3. Confirm the destination reports plan `free` and the operator has active owner membership.
4. Capture the source baseline before any repository transfer.
5. Run the transfer workflow in `dry_run` mode.
6. Review the exact repository list, IDs, visibility, destination, and collision results.
7. Apply transfers with the exact confirmation string generated by the dry run.
8. Serialize transfers and poll each destination repository until its original repository ID is present.
9. Verify the source repository inventory reaches zero.
10. Compare destination repository IDs, names, refs, releases, workflows, secrets/variables names, hooks, environments, and deployments against the baseline.

### 4. Reconcile organization-level resources

Repository transfers preserve repository contents, issues, pull requests, wikis, stars, watchers, settings, repository webhooks, services, secrets, deploy keys, Git history, and Git LFS objects.

Reconcile separately:
- organization teams, membership, and repository grants;
- organization Actions secrets and variables;
- organization webhooks and webhook secrets;
- GitHub App installations and permissions;
- organization projects and discussion settings;
- GitHub Packages ownership and registry-specific associations;
- Pages site URLs and custom-domain DNS;
- enterprise policy, billing, authentication, and audit settings.

GitHub secret values are write-only. Re-enter organization secret values from their approved source or rotate them through the credential owner. Record names and migration state only.

### 5. Apply the WAIT/WATCH cycle

After every commit, workflow dispatch, transfer, or owner operation:

`RE-FETCH SHA → WATCH RUN → INSPECT JOBS/STEPS → VALIDATE EFFECT → RE-FETCH ORG/REPOS → COMPARE BASELINE → CLASSIFY → RECORD → REPEAT`

- ACTIVE: inspect new steps, logs, artifacts, or transfer state.
- QUIET: back off and perform bounded, disjoint work.
- STALLED: classify the failure and change the approach before another attempt.
- BLOCKED: record the exact owner permission, credential, input, or platform restriction.
- TERMINAL: verify the current SHA and requested preservation outcome.

Treat queued, in-progress, HTTP 202, and successful dispatch as admission evidence. Confirm the destination repository ID, Free plan, and asset reconciliation before reporting success.

### 6. Closeout

Record:
- Enterprise and source organization identifiers;
- deletion deadline;
- chosen preservation path;
- baseline run ID and artifact;
- source and destination organization IDs;
- repository IDs and transfer outcomes;
- organization-level resource dispositions;
- Free-plan verification;
- remaining unverified surfaces;
- final terminal state and evidence links.

Use terminal states `PRESERVED_DETACHED`, `PRESERVED_TRANSFERRED`, `PARTIAL`, `BLOCKED`, or `FAIL`. Close the migration only after the selected path and its evidence requirements pass.

## Repository automation

- Runbook: `docs/ops/ENTERPRISE-TRIAL-PRESERVATION.md`
- Baseline/verification: `.github/workflows/enterprise-org-detachment-verify.yml`
- Repository transfer: `.github/workflows/enterprise-org-repository-transfer.yml`
- Transfer implementation: `scripts/github/transfer_enterprise_org_repositories.py`
- Organization-aware repository provisioning: `.github/workflows/repository-provisioner.yml`

## Authority boundary

The skill prepares and verifies migration automation. Organization creation and Enterprise settings operations remain owner actions. Repository transfer apply requires an exact confirmation and the configured operator PAT. Preserve the Enterprise account until the destination and its assets pass verification.
