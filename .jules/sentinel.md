## 2026-08-10 - Local Privilege Restriction and Symlink Hijacking Prevention
**Vulnerability:** Weak default file/directory permissions on local user configuration stores (e.g., ~/.deepcli) and session logs, databases, or telemetry, allowing local users on multi-user environments to read or modify sensitive API tokens and history.
**Learning:** Broad directory creation (e.g., `os.makedirs`) and file writing without explicit permission restrictions defaults to permissive system umasks (such as 0o022 or 0o002), which makes private data readable by other local users. Furthermore, naïve recursive permission updates can follow malicious symlinks introduced inside user folders, causing unintended permission hijacking/traversal across the filesystem.
**Prevention:** Explicitly restrict configurations and session caches (0o700 for directories, 0o600 for files) immediately upon creation. Always use standard recursive permission walkers that inspect `path.is_symlink()` and skip symlinks to prevent traversal-based permission hijacking.
