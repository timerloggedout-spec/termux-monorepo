# Sentinel Security Journal

## 2026-08-01 - Enforcing Strict Credentials File and Directory Permissions
**Vulnerability:** Local configuration and session history caching files (containing sensitive Bearer tokens, cookies, and full chat histories) were written with default file permissions. This would allow other local users or unprivileged processes running on the same local system to read these sensitive assets, violating the principle of least privilege.
**Learning:** This gap existed because the standard Python `Path.write_text` and `open(..., 'w')` APIs do not restrict file creation permissions to the owner (they default to standard system umask, which typically allows group or world readability). Specifying permissions during initial file and directory creation is required to fail securely. Additionally, creation mode (e.g., `os.open(path, ..., mode=0o600)`) only applies to newly created files and does not secure pre-existing files with looser permissions.
**Prevention:** Always enforce `0o700` permissions on directories and `0o600` permissions on files when handling credentials, session caches, or other highly sensitive assets on local storage. In Python, this can be securely achieved by using `os.open(path, os.O_CREAT | os.O_WRONLY, 0o600)` without O_TRUNC, then calling `os.fchmod(fd, 0o600)` on the file descriptor to normalize permissions on existing files, followed by `os.ftruncate(fd, 0)` before writing. This ensures no permission race conditions and that pre-existing files are also secured.
