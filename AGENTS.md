# Agent operating contract

## Mission
Maintain `timerloggedout-spec/termux-monorepo` as the canonical, evidence-backed management hub for research lanes, engineering delivery and reproducible automation.

## Operating rules
- Prefer free-tier services, local execution and open standards.
- Use documented referral, sponsorship or affiliate credits only when eligibility, value, expiry and billing ownership are verified.
- Require explicit approval before any paid resource, usage-based billing, subscription, persistent storage or credit-consuming action.
- Treat GitHub as canonical source and evidence registry.
- Keep Vercel presentation and GitHub Pages fallback deployable from repository sources.
- Treat Render as an optional free-tier adapter; verify plan, sleep behavior, quotas and persistence before provisioning.
- Preserve read-only authority for public observatory feeds.
- Keep secrets server-side; use least-privilege credentials and repository environments.
- Preserve provenance, timestamps, source identifiers, schema versions and freshness.
- Record unavailable evidence as pending or unknown; classify observed failures explicitly.
- Route work by lane ownership and recipient role scope.
- Use Termux-compatible Python standard library, POSIX shell, Git, SQLite and HTTP interfaces where practical.
- Use Wolfram for symbolic derivation and review; keep runtime calculation local and deterministic.
- Use DO statements in chat, comments, commit subjects, pull-request descriptions and operational documentation.
- Prefer CAVEMAN-6 and Siglary operators for concise operational communication.
- Make chat state-change or oversight oriented; route execution through governed repository workflows.
- Attach validation evidence to changes and preserve review gates.

## Change workflow
1. Inspect canonical files, issues, branch state and current checks.
2. Create an isolated branch from the current intended base.
3. Implement the smallest coherent change with tests and documentation.
4. Run deterministic local checks where available.
5. Open a pull request with DO-form summary, scope, validation and cost classification.
6. Observe required checks and review findings.
7. Merge only after required gates pass and authority is established.

## Required hand-off
Every operational integration declares owner, source of truth, free-tier ceiling, credential boundary, health contract, freshness, failure semantics, rollback and evidence location.
