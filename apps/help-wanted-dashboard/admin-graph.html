Edge taxonomy

Every connection is delineated by five channels at once — thickness, opacity, dash pattern, animation, and color. The canvas is generated from the model: nothing is drawn that is not in the model, and nothing in the model is left undrawn (satellite layer permitting).

Groups — collapse / expand

Groups are model data (every node carries a group field, exported as Mermaid subgraphs). Collapsing is view state only: it never dirties the model, never appears in the Δ diff, and exports always show the full model. A collapsed group renders as one summary node; boundary edges aggregate onto it (×N = merged member edges, style = strongest member; internal edges hide and are counted in the header). Workflow families (vercel-*, collectors, bridges) exist as field rows inside the GitHub Actions node. The Delphi family is the exception: delphi-* is its own group below (intake → generate → cross-vote → gate → ledger, wrapped by the cycle), alongside Research, Issues, Competition, and the Proposal flow group that models this dashboard's own submission pipeline. The unclaimed set (GCP / AWS / Azure / Oracle / DigitalOcean) likewise has no model nodes — inventory stubs only — so it has no group.

Focus on a category / family

Focus expands one group (category or workflow family) and collapses every other group. Focus is view state only — like collapse, it never dirties the model and never appears in the Δ diff. Exiting Focus restores the exact collapse state from before Focus was entered.

Dim others: non-focused summaries and their non-boundary edges render at low opacity. Hide others (summaries remain): non-focused groups stay as collapsed summary nodes — never fully invisible — so context and egress edges stay discoverable, with boundary edges of the focused group at full strength and aggregated edges labeled ×N. The same choice applies in the bottom-bar group picker. Fit on focus (third companion, default ON): entering Focus also zooms the camera to fit the focused group's rendered bounds — its members plus the boundary summaries it connects to — with padding; exiting Focus restores the exact pre-Focus camera (scale + translation, snapshotted alongside the collapse state).

Proposal dispatch console — new proposal

This panel formalizes the owner ↔ agent chat loop happening in Muse chat right now: the owner drafts a concept, dispatches it, and gets feedback → review → enhancement → expansion → fit analysis back. Here the same loop is a form + a stage pipeline (the proposal-flow group on the canvas). Submitting = Prepare dispatch: the proposal becomes a draft node in the model (it appears in the Δ diff), wired to the chosen method's target and to every stage node, and the panel emits that method's real payload shape. PREPARED — not sent Sending = a PAT issue POST / workflow dispatch call outside this static prototype; no “sent” state is ever shown here.
