# Challenge 2 submission checklist

The official event requires the LabLab submission for judging. This checklist separates repository work from externally evidenced deliverables.

| Deliverable | State | Evidence / next action |
|---|---|---|
| Public GitHub repository | IN PROGRESS | PR #5035; promote only after review and green checks |
| Product-style application | IMPLEMENTED | Responsive queue, workbench, impact map, decision flow |
| Vultr VM backend | NOT DEPLOYED | Provision VM, configure service and persistent storage |
| Public application URL | NOT AVAILABLE | Configure DNS + Caddy TLS; verify externally |
| Real workflow demonstration | LOCAL/CI FIXTURES | Run signature scenario on the deployed instance |
| Recorded demo video | NOT RECORDED | Follow docs/DEMO-SCRIPT.md |
| Architecture / Vultr explanation | DOCUMENTED | README.md + docs/ARCHITECTURE.md |
| Cover image | NOT CREATED | Prepare a project cover asset |
| Slide presentation | NOT CREATED | Create concise product/architecture slides |
| LabLab entry | NOT SUBMITTED | Submit project title, description, tags, app URL, repository, video and slides |

## Final acceptance gate

Do not mark the entry ready until the app is deployed on a Vultr VM, a public URL is reachable over HTTPS, the signature scenario is exercised remotely, a decision and audit-chain verification are captured, the demo is recorded, and the LabLab form is submitted.
