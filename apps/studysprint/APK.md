# StudySprint APK surface

An Android installable carrying the StudySprint surface
(`android/`): a thin native shell (WebView) over the webApp bundle,
with the core-generated state baked in at build time. No network
is used or requested.

**Architecture, stated first (#4220):** the Python core does NOT
execute on the phone in this version. The core runs at BUILD time
(its outputs — plan, trust receipt, SR cards, reader sections —
are generated by `web/build_data.py` and carried in the APK as
`data/state.json`), and what runs on-device is the bundle: the
screens plus the SR review engines (FSRS via ts-fsrs formulas,
SM-2 baseline) with review state in the WebView's localStorage.
An embedded-Python build (BeeWare/Chaquopy class) is a larger
step and is NOT claimed — the filed spec's "core runs on-device"
requirement is met at the level of the core's outputs and
engines, not the interpreter, and this paragraph is where that
is said, before anything else.

**Version line: independent.** This surface versions on its own
SemVer line (owner overrule 2026-11-03), separate from the
foundation road {core v0.3.0 ⇒ v0.4.0 ⇒ v1.0.0}. Surface version =
`android/VERSION` (and the manifest `versionName`) — currently
**0.1.1** — with its own releases; the built .apk attaches to the
surface's own release.

## Build

SDK-direct, no Gradle (the fleet-apk pipeline):

```
# needs JDK 17 + Android SDK platform 34 / build-tools 34.0.0
ANDROID_SDK_ROOT=/opt/android-sdk bash android/build.sh
# -> android/studysprint.apk (signed with the committed project dev keystore, #4222)
```

`build.sh`: regenerates the core state (`web/build_data.py` runs
the real core) → stages the webApp bundle as APK assets → aapt2
link → javac → d8 → zipalign → apksigner + verify → content smoke
(classes.dex + bundled web + state.json must be inside). In CI:
`.github/workflows/studysprint-apk.yml` builds on dispatch / on
android+web changes and uploads the `studysprint-apk` artifact.

## Signing — the project key (collaborators: read this first)

Every StudySprint APK build signs with the project's committed
DEV keystore:

- **Path:** `android/keystore/studysprint-dev.keystore`
- **Alias:** `studysprint`
- **Password:** `android` (also in `android/build.sh`, which fails
  loudly if the keystore is missing)
- **Certificate SHA-256:**
  `74623c3e84997c495c9aa2bb46891dfd4b3308b7614ac28cb438ff590caf908b`

This is deliberate (owner ruling, 2026-11-03): the key is a
**shared project signing key**, public on purpose. It protects
update continuity, not secrecy — the app is sideload-distributed,
holds no secrets, and never ships through Play.

**The one rule: all builds sign with this key.** Android refuses
to install an update signed by a different key over an existing
install, so a build signed with anything else (an ephemeral CI
key, a local keytool key) silently breaks the update path for
every installed copy. If `build.sh` cannot find the keystore it
stops — never substitute another key to get a build out.

**Rotation** (deliberate, breaking): a new key means existing
installs cannot update in place — they must **uninstall first**
and reinstall. Rotate only in a single announced change that
swaps the keystore file, **bumps `android:versionCode` in
`android/AndroidManifest.xml`**, updates this section and the
fingerprint above, and states the uninstall-first instruction
for installed copies. The collaborators note beside the key
(`android/keystore/README.md`) carries the full procedure,
including how to build + sign. Scope warning: this is a DEV
key for sideload distribution only — never a store or
production key.

## What's on-device

- The full webApp bundle (Today / Plan+Receipt / Reader / SR
  Review) as assets — the same screens and engines as the PWA.
- The core state (`data/state.json`) generated from the real core
  at build time — plan, trust receipt, SR cards + ts-fsrs UX
  export, reader sections.
- SR review runs on-device in the bundle's engines (FSRS via
  ts-fsrs formulas, SM-2 baseline); review state persists in the
  WebView's localStorage on the device.

Stated plainly (and repeated from the top of this doc, #4220):
the Python core itself does not execute on the phone in this
version — its outputs are generated at build time and carried
in the APK; review scheduling runs in the bundle's ts-fsrs/SM-2
engines. An embedded-Python build is not claimed here.

## The smoke gate (#4283)

`android/emulator-smoke.sh` is the release gate: it boots a
headless emulator, installs the built APK, and asserts the
state-loaded signals (no "Loading your course…" hang, footer
version present, process alive), capturing every view as
screenshots + UI dumps + a screen recording (`smoke.mp4`,
#4420 — the recording joins every acceptance run and every
slate-iteration evidence pass). It runs in Actions via
`.github/workflows/studysprint-apk-smoke.yml` (dispatch with a
ref + label; KVM runners) — the owner's device smoke stays the
closer of record, this is the pre-device net.

## Verification

- `tests/test_android_surface.py`: manifest/package/version
  coherence, shell wiring (asset path), build-chain completeness,
  workflow shape.
- CI build run: SDK-direct build + apksigner verify + content
  smoke, artifact uploaded (see the workflow).
- Install/run smoke on a device is the D1 seat's device-lane step
  per the issue's flow.

## Release gates (standing requirement, owner 2026-11-03)

Every iteration of this surface ships only when ALL hold:
- Demo evidence present: screenshots/screen-recording of the demo in
  `evidence/<surface>/` in-tree at the release tag.
- Device frames land header-cropped, always: the status/notification
  band is cropped before any device capture is committed, and frames
  are swept for other PII (notification content, names, account
  hints) before they land.
- Parity statement present: what this surface rides vs the foundation
  version it ships against, and what is honestly absent/pending.
- Parity table in the release body (owner rule 2026-11-03, #4667):
  every release of record from v1.0.0 carries the parity table --
  the release-cut workflow composes it from
  `evidence/PARITY-MATRIX.md` in the TAG tree (ground-truth header
  + capability table verbatim + the file's path at that tag), and
  the cut FAILS if the matrix is absent from the tag tree.
- Tests green for the surface + no foundation regressions.
- **Parity table in every release body (owner rule, 2026-11-03):** from
  v1.0.0 onward, every release of record for this surface carries the
  current surface×core parity table (`evidence/PARITY-MATRIX.md`,
  embedded verbatim from the cut tag by the studysprint repo's
  release-cut machinery). A cut from a pre-matrix tag falls back to a
  named versions-of-record line. Patch cuts included.
