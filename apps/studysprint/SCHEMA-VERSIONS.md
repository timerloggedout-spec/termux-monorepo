# StudySprint — schema-version inventory (#4470)

One discipline for every synced/stored artifact class: an
explicit `schema_version` (or the class's named equivalent),
and readers that **refuse-or-migrate loudly** on mismatch —
never silent best-effort. A version bumps when the shape
changes incompatibly; the reader that refuses names both
versions. This file is the class inventory of record.

| Artifact class | Carrier | Version stamp | Reader behavior |
|---|---|---|---|
| Surface state (bundle + TUI) | `web/data/state.json` · TUI `build_state()` | `schema_version: studysprint-state/1` (core constant `STATE_SCHEMA_VERSION`) | Core `validate_state` raises on mismatch AND on absence. Web reader: a present-but-different version lands in the named load-failure state; absent = pre-discipline legacy, accepted (the bundle ships with its reader) |
| Evidence sets | study_tools evidence documents | `schema: studysprint-evidence-set/v1` (`SCHEMA`) | Assembled fresh by `fetch_study_evidence`; consumers read the stamped schema field |
| SR UX seed export | `sr.ux_state` in state | `format: ts-fsrs/v1` + `generation` (FSRS generation) | Web reader warns by name on generation mismatch (soft: intervals may differ, data still readable) |
| SR progress (browser storage) | localStorage | key `studysprint-sr` (unversioned value; migration = new key) | A shape change ships a new key; the old key is left readable for one release, never silently reinterpreted |
| Reader term bank / exports | .apkg · Obsidian vault · EPUB (when built) | the generating surface's version | Export formats are files, not synced state; their generators pin their own format fields |

**Migration stance.** Producers re-stamp on rebuild — the
bundle state is regenerated by `build_data.py`, so a schema
bump propagates by rebuilding, and `validate_state`
refusing an unstamped document is what forces the rebuild
to happen instead of letting stale state ride.
