HACKATHON DESK

Teammate Guide

A practical route from event selection to verified contribution.

Purpose

Use the Hackathon Desk to discover opportunities, select an existing event, connect a project, understand required participation gates, and track delivery evidence.

1. Select an event

  1. Review the event's official source, format, eligibility and published rules.
  2. Review registration and submission state in the event card.
  3. Check recorded dates and participation gates.
  4. Keep pending registration visible as pending until the source confirms the result.
  5. Treat missing dates as unrecorded; confirm them at the official event source before planning around them.

2. Choose a project

Select an existing project from repository proposal and project records. For a new project, use proposal intake and include the event source, intended outcome, constraints, owner, acceptance criteria and verification plan.

Keep event participation, project ownership, venue execution and teammate responsibilities as separate scopes.

3. Connect through GitHub

Choose your GitHub profile link and use GitHub sign-in for contribution actions. A profile URL is self-selected context. GitHub repository membership and write permissions remain controlled by repository administrators.

Request the access level required for the contribution. The Desk provides navigation and evidence; GitHub enforces the actual permission.

4. Contribute

  1. Start from the repository's current target branch.
  2. Use a focused feature branch.
  3. Make small, attributable commits.
  4. Include the proposal item ID in commit and pull-request context.
  5. Open a pull request with the goal, implementation summary, validation evidence and remaining risks.
  6. Resolve review feedback and re-check the final head SHA.
  7. Follow the event's official submission route and retain its receipt.

5. Preserve source evidence

Use official event links for rules, dates and prize details. Use repository records for proposals, issues, pull requests, CI checks and pipeline receipts. Treat generated feeds as projections with explicit freshness states; source systems remain authoritative.

6. Audio-assisted intake

The planned audio-assisted path obtains participant consent, captures original audio, uses a configured inference provider, preserves source transcript and translation provenance, prefills intake, then requires human review and approval before submission. Provider credentials remain server-side. This workflow becomes available after implementation and privacy checks are complete.
