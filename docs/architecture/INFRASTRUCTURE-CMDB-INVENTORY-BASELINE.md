## 4. Resource classification and field-authority rules

Use these classes consistently:
- **Authoritative configuration:** source explicitly documented as owning a configured fact.
- **Observed evidence:** probe, workflow run, artifact, API response, or operator observation with timestamp and scope.
- **Derived projection:** rebuildable catalog/index/summary generated from other sources.
- **Reference/research:** upstream resource or proposal not yet adopted/enabled.
- **Runtime deployment:** live service/deployment state; not inferred from checked-in code.
- **Unknown/inaccessible:** evidence unavailable in the bounded sweep; never coerce to absent.

For every field, record owning source; source locator and ref/SHA; authority class; environment/tenant scope; update mechanism; observed-at; freshness policy; projection timestamp if derived; owner/writer; consumers; sensitivity/projection class; and known conflicts. A source may own one field but provide only a derived claim for another. Prefer field-level authority over a single global system-of-record label.

## 5. P0 continuation work

1. **Machine-readable sweep receipt:** persist the full tracked path inventory or a deterministic path-manifest artifact, commit SHA, counts, excluded scopes and generator/query method. This document records the snapshot and counts; it does not embed all 8785 paths.
2. **Parse source contracts:** extract schema IDs, entity IDs, writer/workflow relationships, update cadence, source URLs, and freshness/observation fields from machine-readable files and workflow definitions.
3. **Content-search the long tail:** search tracked content and issue/PR history for awesome-list intake, AntigravityCLI, deployment/service manifests, ownership declarations, SLOs, incident records and hidden/resource directories not named “registry”.
4. **Field-level authority matrix:** select a source per field only after comparing candidate sources; preserve disagreements and unknowns.
5. **P0 exit review:** publish counts, exact ref, sources inspected, excluded/inaccessible surfaces, candidate duplicates and unresolved questions. Do not mark P0 complete until the path census and relevant indexes have been reconciled.

## 6. Explicit non-claims

This baseline does not claim all resources are operational, all skills are enabled, all workflows are healthy, all secrets are present/valid, all resource collisions are confirmed, or all external catalogs have been discovered. It does not authorize new polling, secret reads, configuration writes, automatic remediation, or a parallel system of record.
