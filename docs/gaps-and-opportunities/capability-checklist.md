## Reading this table

**termux-monorepo** is the clear standout: strong CI, dependabot, SECURITY.md, auto-merge, and
a mature governance/proposal apparatus. Its real gaps are narrow and mechanical: no CODEOWNERS,
no PR/issue templates, and — until PR #499 lands — no Codespaces support.

**termux-mcp and android-mcp** are small, single-purpose API services (same shape: `package.json`
+ `api/` + `vercel.json`, deployed via Vercel) and are missing most of the org-standard
governance/hygiene pieces that the monorepo has: no SECURITY.md, no Dependabot, no CODEOWNERS,
no devcontainer, no governance-doc pointer. Given their size, the right-sized fix for most of
these is lightweight (a short `AGENTS.md` pointing back at the monorepo's governance docs rather
than a full copy; a small Dependabot config; a short SECURITY.md) — not a full port of the
monorepo's apparatus. Proposed as follow-up work, not invented as urgent.

## What a recurring cadence would look like

This was a one-time first pass. Going forward: re-run this checklist quarterly (or after any new
repo is added to the org), diffing against this version to surface newly-introduced gaps (e.g. a
new repo skipping SECURITY.md) rather than re-deriving everything from scratch. Findings that
imply a cost or an owner-scope decision go through `docs/proposals/` as they did this round;
findings that are plain Tier 0-2 config fixes (CODEOWNERS, PR templates, a Dependabot config) can
go straight to a PR without a proposal detour, same as PR #499.
