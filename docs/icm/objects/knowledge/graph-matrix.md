# Graph Matrix

The **Graph Matrix** is the repository's linkage-integrity map over commits × issues × pull requests × branches. It is owned and written by a single writer (the Graph lane of the Repo Organization tree); this card routes to its records and does not restate census numbers, which change every census run.

## What it is

- The matrix record at `docs/ops/GRAPH-MATRIX.md` states scope, axes, and cell semantics: strict edges (GitHub-native closing references) are kept separate from any-reference edges everywhere.
- The machine census lives at `ops/graph-matrix/census.json` (schema `graph-matrix/v1`), generated by `scripts/graph_matrix_census.py`. Census outputs are derived products — read them through the matrix record, never hand-edit them.
- A separate surface, `docs/graph/` (cross-plane projection, edge schema, visual language), projects the `workspace/llm_map` graph planes for research. Its own header declares it a view, never a source of truth. It is **not** the linkage matrix.

## Read when

- Checking whether an issue, PR, or branch is linked, orphaned, stale, or anomalously unclosed.
- Planning a linkage tranche (backlink comments, disposition routing) — dispositions belong to issue owners; the matrix records, it does not close.

## Connected to

- **owns:** nothing; this card is a pointer. The Graph lane owns the matrix and census.
- **joins:** the Context Relationship Index card (bounded PR-evidence graph — a different, narrower graph), issue/PR triage, and branch hygiene.
- **looks-like-but-is-not:** a narrative of repository history (that is Repo-Story / Commit Replay) or an activity rollup (the Tracking lane consumes this matrix; it is not one).
