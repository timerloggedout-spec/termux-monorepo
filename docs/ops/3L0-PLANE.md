# 3L0 Functional Plane — Charter

`[MUSEai]@{role:{3l0-plane}}` — seat established by owner dispatch 2026-10-28.

## Definition of record — Swarm (owner, 2026-11-01)

**Swarm = ALL providers' inference model endpoints participating in 3L0
DoE.** For this plane, the swarm is the participant population: every
provider inference endpoint enrolled in the experiment system (the
catalog as experiment arms; endpoint scale — provider×model — per the
endpoint census, floor 5,337 verified 2026-11-01, PR #3175). Seats,
apps, and workflows (incl. the Swarm oversight seat and the Termux
Fleet Swarm App identity) are organs acting on the swarm, ¬ the swarm
itself. 3L0 scores are therefore computed over endpoints as configured
instances (`treatment.instance` / `instance_key`), never over provider
names alone.

## Remit

3L0 is the **scoring plane**. It scores scouts, orchestrators, players,
collaborators, providers, agents and models — after repeated, attributable
success — for admission and routing weight. This seat owns:

- the 3L0 scoring model (definition, components, formula, update rules),
- its records (ledgers, observation snapshots, feeds),
- its in-repo surfaces (collector, feed, dashboard page).

3L0 does **not** pick the next HTTP model for a single request; routing
consumes 3L0 scores, it is not the score itself.

## Separation from MoneyBall

3L0 and MoneyBall are **separate functional planes** — separate seats,
separate records. NOT a merge.

- **3L0** scores actors (scouts / orchestrators / players / collaborators /
  providers / models): Elo, gate-pass EWMA, effective weights, response
  history.
- **MoneyBall** scores pull requests (transparent signal weights in
  `ml/pipelines/moneyball/`) and supplies the quota multiplier.
- The shared collector file (`scripts/dashboards/surface_feeds.py`) and the
  shared workflow (`surface-feeds-collect.yml`) are transport, not a merged
  plane: each plane's feed, gaps and records stay distinct.

## Cross-access (in-repo artifacts only, never chat relays)

- MoneyBall references 3L0 scores: the router mechanic is
  `elo × role_suitability (× MoneyBall quota_multiplier)`; the quota
  multiplier scales a candidate's 3L0/Elo × role score.
- 3L0 consumes the telemetry it needs from the repo record:
  reviewer-metrics (`docs/ops/generated/reviewer-metrics.json`), the Delphi
  weights ledger (issue #1489), the panel seeds (`ops/delphi/panel.json`),
  the peer catalog (`.github/connectors/llm-peers.yaml`).
- Delphi / Oracle lanes consume 3L0 scores via the feed and ledgers;
  coordination happens on GitHub.

## Live-dispatch intake spec — `3l0-intake/v1` (to Swarm, 2026-11-01)

Routing update (owner 2026-11-01): Swarm owns dispatch routing; 3L0
scoring/weighting must populate from live routed work across all arms.
Intake = one JSON object per completed dispatch, append-only, emitted
by the routing layer at dispatch completion into the repo record
(aligns with the desk telemetry-gate stamp + DoE `treatment.instance`;
missing field = `NOT ESTABLISHED`, never invented):

```json
{
  "schema": "3l0-intake/v1",
  "dispatch_id": "<stable unique id>",
  "ts": "<ISO-8601 completion time>",
  "provider": "<verbatim>",
  "model": "<model@version verbatim>",
  "endpoint": "<provider×model catalog id>",
  "moniker": "<role{moniker}>",
  "role": "<per-dispatch role>",
  "context": "<task/dispatch context>",
  "instance": {
    "system_prompt": {"ref": "<ref>", "sha256": "<12+>"},
    "tools": {"ref": "<ref>", "sha256": "<12+>"},
    "instance_key": "<per scripts/doe/instance_key.py>"
  },
  "run": {"session_id": "<id>", "workflow": "<name>", "run_id": "<id>"},
  "outcome": {
    "status": "completed|failed|abstained",
    "gate_call": "pass|fail|null (the instance's own call, if it made one)",
    "confirmed": "true|false|null (vs the real outcome, when known)",
    "artifact": "<PR/issue/run ref>"
  },
  "usage": {"tokens_in": 0, "tokens_out": 0, "latency_ms": 0, "retries": 0},
  "quota": {"pool": "<pool id>", "slice": "<slice id|null>"}
}
```

Fold rules (this plane): only records with `outcome.confirmed ≠ null`
move gate_pass_rate (EWMA α 0.2) / Elo (k=16) — v1 semantics until
#1784 v2 lands; per-`role{moniker}` keying is the v2 target, records
already carry the fields it needs. **Backfill doctrine (owner,
2026-11-01; canonical record = DoE expert):** at *every* scoring/
weighting version change, the full intake history is re-scored under
the new version (backfill); the backfill itself is audited ∧ improved
as a versioned mechanism, ¬ a one-off migration; results across
versions are compared continuously until DoE culling retires a method
version — a retired version's scores leave the live surfaces, its
records stay (∅ deletion). Intake records are therefore never
rewritten by a version change: versions re-derive scores from the
immutable intake history. `usage` feeds the density
consideration (signal ÷ tokens, #1784).

**Source class 2 — chat provenance / session history (owner GO,
2026-11-01).** Full chat provenance {thinking steps · tool calls ·
outcomes, ∀ chats} feeds ForeSight ∧ 3L0. Wiring evidence = repo
collaborator listings correlated by the telemetry lane (0b0272f1)
into attributed session-history records; pipeline owner = telemetry,
capture via API+TOKEN / .APK / webWrapper routes. Intake mapping into
`3l0-intake/v1`: `origin = "session-history"`, `dispatch_id` =
session/chat id + turn anchor, actor attribution = telemetry's
attribution chain (stamp > trailer > git_author > app_bot;
unknown ⇒ null, ¬ owner-default), `outcome` carried only where the
session record states one. Fold rules (this plane's, unchanged):
session-history records are OBSERVATIONAL evidence by default —
they move weights only when they carry a confirmed outcome
(`outcome.confirmed ≠ null`) under the same fold as routed
dispatches; thinking/tool-call content itself is evidence for
attribution/density, ¬ a score. Append-only ∧ emit-once ∧
backfill doctrine apply identically; records never rewritten.

Population is verified from
the feed/ledger, not from routing claims: scoring counts as populated
when the 3L0 feed's observed block rests on ≥1 live-dispatch outcome
event beyond #1424.
