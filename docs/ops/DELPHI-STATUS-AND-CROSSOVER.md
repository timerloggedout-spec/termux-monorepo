## Architecture correction — generation-first (owner, 2026-10-27)

The owner reversed the architecture this lane was running under.
**Proposals for competitions, RFPs, provider-extension research, and
like surfaces are to be GENERATED by the Oracle Method system.** The
gate, ballots, weighting, and ledgers are the *evaluation layer* over
what the system generates — not the product.

The gap, honestly: the proposal registry (`docs/proposals/registry.yaml`)
holds **41 proposals; the authorship audit of 2026-10-27 counts ChatGPT
11, timerloggedout-spec 8, grok 7, Manus 7, Claude 2, others 6 — and
oracle-authored: 0.** Every existing proposal arrived authored by a
collaborator (the Strands RFP's MANIFEST names ChatGPT), and Delphi sat
downstream as judge: baseline comparator, gate, ledgers, zero generated
proposals, zero ballots. Generation was the unbuilt half.

What changed (2026-10-27): the generation path is built —
`scripts/delphi/generate_proposal.py` + `.github/workflows/delphi-generate.yml`
(dispatch-only; renders to an artifact, never commits). Input is an
evidence set in the `fetch_evidence` schema (the D0 tool is the intake
end of this pipeline) plus a structured brief; output is a proposal in
the registry format (MANIFEST / ITEMS / RFP + a PROVENANCE generation
receipt), provenance-stamped, with unresolvable points marked
UNVERIFIED — never asserted, never dropped. First generated artifact:
`docs/proposals/active/delphi-desk-builder-io/` (competition proposal
for challenge packet D3), registered with `author: oracle-method`.

**Divergences — flagged, not overwritten:**

1. **Authorship.** Historically Delphi judged *externally authored*
   RFPs (issue-form intake `delphi-rfp.yml`; the Strands RFP authored
   by ChatGPT). Generation-first reverses the authorship side per the
   owner's 2026-10-27 correction; the evaluation machinery is the
   historical one, unchanged in formula and ledgers.
2. **Round semantics.** The gate's rounds 2–3 are *feedback* rounds
   (median / IQR / anonymous outlier reasons; stop at IQR ≤ 4 or
   range ≤ 6, max 3) over RFP scores. The method cycle's round 2 is an
   *evidence* round on implementation results — owner-specified at
   exactly 2 rounds. Both coexist: convergence parameters govern the
   gate panel; `generation.cycle.rounds` governs method passes.
3. **Ledger surface.** Calibration records are a new outcome type on
   the existing append-only ledgers (`delphi-generation-ballot v1` /
   calibration feed), extending — not replacing — the
   `delphi-outcomes v1` tribute format and the `delphi-weights v1`
   state format.
