# Hex Non-AI Trial Lane

**Status:** trial activation plan  
**Contract:** `3l0.moneyball.v1`  
**Control plane:** GitHub Actions  
**Analytics/evidence plane:** Hex  
**AI-credit policy:** deterministic work first; reserve Agent credits for ambiguity only

## Purpose

The Hex trial is useful even when Hex Agent credits are exhausted. The core notebook/app execution surface can still query connected data, run SQL/Python, render charts, publish an App, refresh results, and—on Team/Enterprise—schedule published App runs and alerts.

This lane therefore treats Hex as a governed **analytics product**, not merely an AI chat surface.

## Trial deliverables

1. **Evidence landing** — import the privacy-preserving Moneyball NDJSON/CSV evidence generated by GitHub Actions.
2. **Deterministic validation notebook** — schema, nullability, enum, uniqueness, referential-integrity, timestamp, SHA, and privacy checks.
3. **Freshness panel** — separate clocks for Linear issue lifecycle data, GitHub PR/workflow evidence, and generated export artifacts.
4. **Moneyball scorecard** — deterministic/provisional scoring only where required inputs exist.
5. **PR effectiveness panel** — review rounds, head-SHA progression, requested-changes → subsequent-head evidence, and merge/outcome correlation.
6. **Proposal/SLA quarantine panel** — expose missing SLA fields rather than imputing them.
7. **Research/adaptation radar** — source, capability, compatibility, evidence date, adaptation value, disposition.
8. **Published App** — a durable trial artifact that can be opened without an Agent prompt.
9. **Scheduled refresh** — use Team-plan scheduled runs where available; otherwise document the manual refresh cadence and freshness state.

## Data contract rules

Every imported snapshot should expose:

- `contract_version`
- `snapshot_id`
- `source_observed_at`
- `source_sha` / source ref where applicable
- `pagination_exhausted`
- `corpus_complete`
- `validation_status`
- `freshness_seconds` or an equivalent age metric
- provenance/source identifier

Do **not** manufacture absent SLA, score, cost, provider, prompt, completion, credential, or tool-payload fields.

Keep Linear freshness and GitHub/PR freshness on independent clocks. A fresh PR mirror must not silently refresh stale issue lifecycle metrics.

## Credit discipline

Avoid Agent/Thread calls for deterministic transformations that can be expressed as SQL, Python, or chart logic. Agent credits should be reserved for:

- ambiguous schema interpretation;
- high-value synthesis across validated datasets;
- targeted investigation where deterministic queries cannot resolve the question.

The current Hex credit exhaustion therefore does **not** block the deterministic analytics lane.

## GitHub → Hex transport

The repository already provides a privacy-preserving export path:

`GitHub Actions → sanitize → privacy assertion → artifact → Hex import`

The sanitizer emits only supported stable metadata and hashes free-form messages instead of exporting their contents. The workflow also asserts that forbidden raw-content/credential fields are absent before publishing the artifact.

## Freshness/accuracy gate

A panel is considered trial-ready only when it can answer:

1. What source produced this result?
2. When was that source observed?
3. What repository SHA/ref was in force?
4. Was pagination exhausted?
5. Is the corpus complete or partial?
6. Which fields are missing?
7. Which calculations are deterministic versus provisional?
8. Can the result be reproduced from the recorded snapshot?

## Promotion rule

Hex is the analytical/evidence presentation layer. GitHub remains the governed execution plane. Hex output must not directly merge PRs, close issues, deploy services, or mutate repository control state.

See `docs/ops/HEX-MONEYBALL-INTEGRATION.md` and `docs/ops/WOLFRAM-HEX-BRIDGE.md` for the broader architecture.
