# Oracle Panel feed — data contract

The dashboard's Oracle Panel shows Delphi proposal results. This
document is the contract for its data; the Delphi lane owns it. The
Web Design lane builds the rendering (`oracle.html`); the rendering
must consume this feed and nothing else.

## The feed

- **File:** `apps/help-wanted-dashboard/data/oracle-panel-feed.json`
  (the dashboard's own data directory — the deployed panel can only
  serve files inside the app; v1 briefly landed the feed under
  `docs/ops/generated/` and relocated it here the same night)
- **Schema:** `oracle-panel-feed/v1`
- **Collector:** `scripts/delphi/oracle_panel_feed.py` (stdlib only)
- **Refresh:** regenerated by PR (workflow
  `.github/workflows/oracle-panel-feed-collect.yml` — dispatch,
  weekly, and pushes touching the source paths) — never committed
  directly by the collector, mirroring the reviewer-metrics pattern.

## Sources (the records of truth)

| Feed content | Source |
|---|---|
| Which proposals exist, titles, statuses | `docs/proposals/registry.yaml` — oracle-method entries only |
| Generation provenance, evidence counts | `docs/proposals/active/<id>/PROVENANCE.json` |
| UNVERIFIED points | the `## Unverified / open` section of each `MANIFEST.md` |
| Round rankings, ballots by class, per-class scores, classes absent | `docs/proposals/passes/<pass-id>/cycle/BALLOT-round*.json` |
| Expectations (priors, recorded before implementation) | `.../cycle/EXPECTATIONS.json` |
| Implementation results per candidate | `docs/proposals/passes/<pass-id>/implementation/<candidate>.json` |
| Calibration deltas | `.../cycle/CALIBRATION.json` |
| specified_not_run stages | `.../cycle/CYCLE.json` stage records + the ledger ballot payload |
| Ledger linkage | outcome ledger issue #1487 comments (`delphi-generation-ballot v1`, `delphi-generation-calibration v1`) |

## Honesty rules (binding on the rendering)

1. **Show only what the record holds.** A value absent from the
   sources is rendered as absent/null — never synthesized, never
   backfilled from a similar proposal.
2. **Ballot classes read as recorded.** Where no human or model
   ballots exist, the class reads 0 and appears in `classes_absent`.
   A class at zero is not implied support and must not be rendered
   as participation.
3. **UNVERIFIED and specified_not_run are first-class statuses.**
   They render as visible states, not as footnotes or omissions.
4. **Rehearsals are excluded.** Oracle Method rehearsals are
   ideation drafts imagining readiness (synthetic fixtures, no real
   ballots, not registered). They are named in the feed's
   `excluded` block so the exclusion itself is auditable; they are
   never results.
5. **Ledger verification is stated.** `sources.ledger_verified`
   says whether this refresh read the ledger; per-proposal
   `ledger.verified` carries the same fact down. An unverified
   refresh shows repo-record values and says so.

## Validation duty

The Delphi lane validates the panel's rendered output against the
registry and this feed before the design lane merges changes to the
panel — figures, rankings, statuses, and labels are checked against
the records, and discrepancies are resolved in favor of the records.
