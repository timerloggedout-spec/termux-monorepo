# Provider and collaborator capability map

**Implements: MSM-019**

**Snapshot:** repository checkout on 2026-10-21; contracts are declarations unless identified as workflow implementation or observed GitHub event.

**Purpose:** map collaborator identity/role, capability boundary, context delivery, tool bindings, and attributable participation without equating a provider, model, GitHub actor, or API credential.

> **Evidence rule:** declared capability ≠ implemented dispatch ≠ verified execution/action. A configured secret reference does not establish a live credential, account entitlement, or usable provider scope. A shared PAT/GitHub App actor does not identify the model behind an action. Never infer a provider/model from commit author or workflow actor.

## Tool scopes, MCP and evidence levels

- **GitHub job permissions:** workflow `permissions` and each job's `permissions` bound the token. E.g. Gemini review job is contents read plus issues/PR write; peer-review orchestrator's collector is contents/PR read plus issues write; DeepSeek Termux Agent declares broader contents/issues/PR write and actions/checks read. A workflow's permission declaration is not proof that the job ran or its token could exercise every operation in every repository.
- **App scopes:** CodeRabbit's documented scope gap above is concrete. For other installed apps/Tembo, current live installation grants and account entitlements are **unknown/not checked**. Provider API keys are not GitHub scopes.
- **MCP:** repository split is stateless/read-only `mcp-hub` vs device-touching `hub_mcp`; no default device authority. See [MCP risk-split debate](../proposals/active/mcp-hub-risk-split/DEBATE.md). Presence of MCP endpoint/documentation or Tembo's platform-managed MCP declaration does not identify tools, grants, operator, or a successful call. No live MCP inventory was available in this read-only audit.
- **Context:** ICM's map points to one relevant process/object card; task adapters must provide scoped issue/PR, base/head SHA, relevant source/evidence and any explicit output contract. No complete per-provider prompt/context transport or fingerprint is established by role docs. Never claim that a provider saw a cited path unless invocation-bound evidence records it.
- **Attribution:** correlate workflow run/attempt, job/step, triggering event, issue/PR, head and commit SHA, provider, model, adapter, role, reviewer state/comment and confidence. PAT actor, commit author, workflow actor, moniker and model remain separate fields. Follow [throughput/provenance contract](AGENT-TEAM-ORCHESTRATION.md) and [event schema](AGENT-THROUGHPUT-EVENT.schema.json).
