# Provider quota managers (MSM-019)

This is an **offline metadata registry and passive normalizer**, not another quota poller. It makes no provider calls, reads no credentials, mutates no account, and does not affect runtime admission. A parser being implemented is not evidence that it ran against an account or that the account's state is known.

## Interface

- `ops/quota/provider-managers.json` is the SSOT; its `provider_families` array has one row per canonical family.
- Dashboard/consumer interface: `scripts.provider_quota_managers.build_public_metadata()` returns `{schema, provider_families, network_used, live_account_validation, runtime_admission}`. This is **static public metadata only**. It contains no account observations.
- `normalize_observation(family, headers=..., metadata=..., observed_at=..., scope=...)` is an offline parser for only the named official documented signals. It returns a private observation object with an explicit caller-supplied scope and UTC observation time. Keep that return private; do not publish raw or normalized account values. Missing signal means `unknown`, never zero.
- `implemented_passive_adapter` means only that an offline parser exists for specific documented fields. `public_documentation_only` means official documentation exists but no parser/verified counter contract was implemented. `unsupported` means the official page found does not establish quota semantics. Neither status implies live validation.

Counters are non-negative finite numeric values; timestamps must be timezone-aware ISO-8601; scope must be explicit and bounded. Unrecognized fields and raw payloads are discarded. Reset strings are not converted to absolute reset timestamps unless the source explicitly supplies one. No inferred reset, remaining balance, entitlement, or quota is produced.

The repository's 20 canonical names are taken dynamically from `_providers()` in `scripts/provider_quota_coverage.py`; manifest completeness does not mean the 18 prior gaps are closed as live managers. Statuses describe **checked-in mapping/parser capability**, not account validation, provider availability, freshness, or runtime coverage. Caller-provided scope is labeled `caller_declared_unverified`; provenance or account/model association is not authenticated. Compatible transport does not imply compatible quota semantics.

## Explicit non-goals and separate follow-up

No new live polling, account calls, credential mutation, public private-observation output, paid fallback, retry, account/key hopping, entitlement inference, reservation, quota admission, or production admission change. The integrated coverage/dashboard exposes static manager capability separately from unknown account evidence. The existing poller's documented OpenRouter reader now validates its request-counter triplet, while its public workflow exports only a status projection and withholds raw values/logs; private CLI consumers retain their separate default output. Review further official schemas before adding parsers. Existing router reconciliation in PR #1441 remains separate.
