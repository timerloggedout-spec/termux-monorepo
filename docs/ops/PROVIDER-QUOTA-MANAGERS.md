# Provider quota managers (MSM-019 / MSM-020)

This is an **offline metadata registry and passive normalizer**, not another quota poller. It makes no provider calls, reads no credentials, mutates no account, and does not affect runtime admission. A parser being implemented is not evidence that it ran against an account or that the account's state is known.

## Interface

- `ops/quota/provider-managers.json` is the SSOT; its `provider_families` array has one row per canonical family.
- Dashboard/consumer interface: `scripts.provider_quota_managers.build_public_metadata()` returns `{schema, provider_families, network_used, live_account_validation, runtime_admission}`. This is **static public metadata only**. It contains no account observations.
- `normalize_observation(family, headers=..., metadata=..., observed_at=..., scope=...)` is an offline parser for only the named official documented signals. It returns a private observation object with an explicit caller-supplied scope and UTC observation time. Keep that return private; do not publish raw or normalized account values. Missing signal means `unknown`, never zero.
- `implemented_passive_adapter` means only that an offline parser exists for specific documented fields. `public_documentation_only` means official documentation exists but no parser/verified counter contract was implemented. `unsupported` means the official page found does not establish quota semantics. Neither status implies live validation.

Counters are non-negative finite numeric values; timestamps must be timezone-aware ISO-8601; scope must be explicit and bounded. Unrecognized fields and raw payloads are discarded. Reset strings are not converted to absolute reset timestamps unless the source explicitly supplies one. No inferred reset, remaining balance, entitlement, or quota is produced.

## Continuation: source-confirmed implementation and deliberate gaps

Ollama moves from documentation-only to a sixth passive adapter: eleven families remain documentation-only and three remain unsupported. Its official endpoint permits ten requests/minute/user, shared across keys/devices, and recommends once/minute. HTTP 429 has seconds-valued `Retry-After`; no scheduling or retry is installed here. The separate transport has no default network implementation or credential/environment discovery, accepts only an explicitly injected transport, and returns private results. It was not invoked against an account. A production integration must still establish authorization, account/Team association, freshness, reset handling and shared reservation. USD balances cannot be passed to the request-count quota evaluator.

Additional official research preserves the distinction between usage and capacity:

- [Cloudflare Billable Usage API](https://blog.cloudflare.com/billable-usage-api) exposes account service-period consumption/cost through a Billing Read bearer token, updated daily. It is not remaining Workers AI entitlement; charge-period bounds are not quota resets. No remaining parser is added.
- [Kilo usage/billing](https://kilo.ai/docs/gateway/usage-and-billing) and [API reference](https://kilo.ai/docs/gateway/api-reference) describe per-inference usage/cost and shared pools, not a documented balance endpoint. No inference is issued to collect usage.
- [LLM7 limits](https://docs.llm7.io/limits) document rolling allowances, not a remaining-counter/reset API. [Cerebras usage monitoring](https://inference-docs.cerebras.ai/console/usage-monitoring) provides console analytics/CSV exports, not a verified API counter contract.
- Mistral's named remaining header still lacks verified metric/reset semantics. NVIDIA hosted and self-hosted products must not be conflated. OVHcloud's project/model limits and console metrics do not supply a verified remaining/reset schema. Gemini, Cohere, ModelScope and Z.ai remain documentation-only for the reasons in the table.

## Explicit non-goals and separate follow-up

No new live polling, account calls, credential mutation, public private-observation output, paid fallback, retry, account/key hopping, entitlement inference, reservation, quota admission, or production admission change. The integrated coverage/dashboard exposes static manager capability separately from unknown account evidence. The existing poller's documented OpenRouter reader now validates its request-counter triplet, while its public workflow exports only a status projection and withholds raw values/logs; private CLI consumers retain their separate default output. Review further official schemas before adding parsers. Existing router reconciliation in PR #1441 remains separate.

## MSM-022: opt-in runtime balance service

`scripts.provider_quota_service` now implements a separately invoked production HTTP path for the existing Ollama contract, registered as `ollama.balance`. This is not the passive parser, an automatic poller, or a request-count admission manager. The default transport performs one verified-TLS GET to exactly `https://ollama.com/api/balance`, with bounded socket timeouts and body size, no redirects, proxies, retries, alternate endpoints or inference. Duplicate JSON fields, nonfinite values, invalid/mixed variants and non-200 responses fail closed. A 429 is unknown balance, never zero remaining quota.

The caller explicitly selects `OLLAMA_API_KEY` and a private scope alias for that credential-selected user or shared Team. The authenticated source does not return account/Team identity, so `scope_status` remains `credential_selected_user_or_team_identity_unverified`. No independently verified account binding, model entitlement, reservation or request/token capacity is asserted. Modern USD pools and legacy percentages retain their own units. Included periods must cover the observation time; legacy resets must be in the future. The private `valid_until` expires at the earlier of sixty seconds or the next source-supplied reset; purchased-credit expiry/reset is not invented.

The opt-in CLI requires `--observe`, `--service ollama.balance`, `--scope <private-alias>` and `--private-out <new-file>`. It reserves an exclusive mode-0600 output file in a current-user-owned mode-0700 directory outside Git worktrees **before** reading the environment key or making any request. It refuses overwrite/symlink destinations. It prints only allowlisted service/provider/status/observation-time metadata; private values, aliases, resets and hashes are not public output. Unknown results are retained privately and exit nonzero. The caller owns private retention and explicit refresh; no schedule or shared reservation is installed. Never commit or upload these private files to public artifacts.

This implementation was validated with synthetic responses only. No live account observation occurred. `quota_poll.LIVE`, automatic collection, routing weights, router admission, credentials and schedules are unchanged. Coverage now separates three actual registry mappings, one opt-in private service implementation, six passive adapters and unknown live account state. This closes one implementation/registry gap, not a live-account-validation gap.
