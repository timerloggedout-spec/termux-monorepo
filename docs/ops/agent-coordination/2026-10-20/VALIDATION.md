## Evidence gathered for this validation
1. **Lineage inventories (AST, current files).** Master deepagent.py: 1,151 lines, 34 functions. Device deepagent.py at #1027 head: 2,016 lines, 46 functions. Common names: 33. All files compile.
2. **The device-only surface is 13 functions, in four clean clusters:**
   - Worktree provenance: `_wt_bases_load`, `_wt_bases_save`, `_wt_default_repo_branch`
   - Hygiene: `hygiene_preflight`, `post_loop_cleanup`
   - Resource-pressure telemetry: `_log_dir_size_mb`, `_mem_kb`, `_swap_free_kb`, `_worktree_count` (the machinery behind the user's 'Termux Resource Pressure' alerts)
   - Feedback loop: `_auto_feedback`, `_feedback_call`, `_maybe_continue`, `_validate_finish_summary`
3. **Correction to the brief:** master DOES have `_gh_worktree` — a simpler version without the base-provenance helpers. The brief's "absent entirely" is wrong for that one function; the port is an augmentation + reconciliation of `_gh_worktree`, not a green-field add.
4. **Divergence is broad, not additive:** 29 of the 33 common functions differ in body size between lineages. Any direct merge/rebase of the device file onto master is a hand-adjudication of ~29 functions — B-as-canonical (or any wholesale merge) fails on this alone.
5. **Only-in-master:** exactly one function name, `run` — the port/checklist must account for it explicitly.
6. **#924 split fidelity check:** the recapitulation package at #924 head compiles cleanly and holds 53 function names vs 48 unique in current master's deepagent+agent. Delta: recap carries `_auto_feedback`, `_feedback_call`, `_maybe_continue`, `_validate_finish_summary` (the feedback quartet — so part of the "device" surface already lives in #924's tree, which was cut from a tree that had them), plus `_hindsight_active` (the dead-code target #914 removes) and `_spec`; and it lacks `run`. **Conclusion: the split is not a blind mechanical move of current master — it needs an explicit function-inventory gate adjudicating those 7 names before landing.**
7. **Known-working-state test (the user's principle, applied):** master passes it (entrypoint 4/4, doctor contract, CI + Termux runner wired). The device lineage fails it: compiles, but its flagship machinery shipped with the `{{}}` TypeError and an undefined helper, and it has no green entrypoint evidence. Pure B is therefore disqualified by the user's own rule. Pure A passes the principle but re-creates the ~2,000-line monolith — the shape that diverged.
8. **Performance, honestly scoped:** modular vs monolith has ~zero runtime cost (Python imports once); nobody should pick a path for engine speed. The real performance levers are (a) blast radius — module-scoped tests and CI instead of a 2,000-line file, (b) revertibility per step, and (c) **execution placement** — see the classifier note below. On risk-adjusted, compounding terms the hybrid dominates each pure option.
9. **Classifier execution architecture (user, 2026-10-20 17:54 PDT):** the classifiers in `deepcli/*` (verified on master at `deepcli/deepcli/observatory/`: kev.py, laya.py, trial.py, tests) are intended to execute via **Actions Workflows**, with hosted services (**HuggingFace** hosts some — 39 HF references verified across the repo, including scripts/decision_engines.py and provider catalogs) for everything initially; **on-device provisioning is a later investigation**, with the device's role being to **offload as much compute as possible**. Existing pattern piece: `.github/workflows/deepagent-task.yml` already dispatches from Actions to the Termux device over the Pinggy SSH tunnel (manual dispatch, secrets pending). A dedicated classifier-dispatch workflow is a build item, not an existing artifact — none was found in this pass.

## Verdict
**The CAB hybrid is validated and is the best path**, with two amendments the evidence forces:
- **Amendment 1 (inventory gate on Phase C):** land #924 by rebase-by-content only against an agreed function inventory: current master's inventory, plus explicit verdicts on the recap-only names (feedback quartet: keep — they are wanted machinery and arrive free with the split; `_hindsight_active`: remove, folding #914's cleanup into the split instead of a separate step; `_spec`: adjudicate at port time) and on `run` (must survive the split). Gate stays: entrypoint 4/4 + py_compile everywhere + dual repo gates.
- **Amendment 2 (shrunk Phase B→A):** after the split, the true device-only remainder is 9 functions (worktree trio + hygiene pair + resource-telemetry quartet) plus reconciling the diverged `_gh_worktree` — ported as one `recapitulation/worktree`-style module with #1027 + #1067 fixes included, #1067's persist test carried, and #1059's invariants pointed at the module. The feedback quartet needs no port (Amendment 1 keeps it from #924's tree) but does need its tests/verdicts at split time.
