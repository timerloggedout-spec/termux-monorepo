# B2 — Workflow Surface Evidence

**Status:** Implemented on `fix/ar01-automation-baseline`; pending GitHub pull-request publication and review.  
**Ledger items:** AR-03, AR-06  
**Owner workflow:** `.github/workflows/workflow-surface-evidence.yml`

The B2 control adds a real same-run producer-consumer pair for deterministic workflow-surface test evidence. It does not move session state, browser data, credentials, prompts, repository checkout contents, or device data. The producer creates exactly one test-output file and one SHA-256 manifest; the consumer downloads the named artifact only after the producer job and independently verifies the file list, byte size, and digest.

> Artifact immutability does not replace content validation. The consumer verifies the explicit manifest after download and rejects missing, duplicate, hidden, traversal-shaped, oversized, or digest-mismatched evidence.

## Runtime Contract

| Property | Control |
|---|---|
| Producer evidence | `evidence/policy-tests.txt`, generated by two deterministic standard-library test suites. |
| Allowlist | The manifest generator accepts only one non-hidden, single-component filename; maximum file size is 1 MB. |
| Manifest | `evidence/evidence-manifest.json`, schema version 1, with SHA-256 and byte count for every allowlisted file. |
| Artifact name | `workflow-surface-evidence-${GITHUB_RUN_ID}-${GITHUB_RUN_ATTEMPT}`; unique per run attempt. |
| Upload | Immutable `actions/upload-artifact` v4.6.2 SHA, finite seven-day retention, hidden files disabled, and failure on a missing evidence directory. |
| Dependency | The consumer declares `needs: produce`; it downloads only `needs.produce.outputs.artifact_name`. |
| Download | Immutable `actions/download-artifact` v4.3.0 SHA into a fresh directory. |
| Verification | A separate verifier checks manifest schema, safe path shape, duplicate names, file existence, byte size, and SHA-256 digest. |
| Permissions | Both jobs are read-only; no artifact data is interpolated into a shell command or used to gain repository authority. |

## Fixture Coverage

The focused tests cover digest construction, traversal and absolute path rejection, hidden-file rejection, missing evidence, duplicate entries, oversized files, and consumer rejection after evidence tampering. The workflow preserves and uploads the test-output artifact even when tests fail, so the consumer can validate evidence integrity while the producer retains the correct failing conclusion.

## Promotion Boundary

This contract is limited to a known, non-secret test record. A future artifact hand-off must create its own explicit allowlist, manifest schema, retention rationale, and consumer validation. Existing artifacts, including `deepseek_output.json`, are not implicitly enrolled.
