# B3 — Read-Only Agentic Operations Pilot

**Status:** Implemented; controlled runs verified the no-secret inference and failure-reporting boundaries, while exposing an unsupported explicit model override. The documented default-model fallback is under review.
**Ledger item:** X-05 / B3
**Source:** `.github/workflows/agentic-repository-operations-report.md`
**Generated lock workflow:** `.github/workflows/agentic-repository-operations-report.lock.yml`

The B3 pilot provides one weekly, advisory repository-operations report. The agent may use only GitHub issue and pull-request reading tools. It cannot write repository content, comments, labels, assignments, pull requests, dispatches, or external requests. It can emit either a `noop` record or exactly one structured `create_issue` request. A compiler-generated, separate safe-output job is the only job with `issues: write`; it cannot write code, create a pull request, comment, dispatch a workflow, change labels, or change repository state.

> The source is Markdown, but the executable artifact is the reviewed `.lock.yml` file. The lock file is regenerated by `gh aw compile` and SHA-pins its generated Actions dependencies.

| Surface | Bounded control |
|---|---|
| Trigger | Weekly Monday schedule plus `workflow_dispatch` for a controlled trial; no issue, comment, pull-request, push, or repository-dispatch trigger. |
| Agent permissions | `contents: read`, `issues: read`, `pull-requests: read`, plus `copilot-requests: write` solely for organization-billed Copilot inference. The agent retains no repository-content, issue, or pull-request write permission. |
| Tools | GitHub issues and pull requests only. The source prohibits browser, shell, edit, network, MCP, and write-capable GitHub tools. |
| Output | `create_issue` only, `max: 1`, title prefix `[agentic-ops]`, title de-duplication, and an allowed GitHub-reference set of `[]`; `noop` remains the non-writing system output. |
| AI cost | Main agent: maximum 40 AI Credits per run, 80 per 24 hours, four turns, and eight minutes. Threat detection: a separate 20-AI-Credit cap. |
| Injection boundary | All user-authored repository content is explicitly untrusted. The report must not reproduce issue/comment body text or follow embedded instructions. Compiler-generated threat detection runs before the safe-output job. |
| Output contract | The report schema requires a dated fixed-format title and five ordered headings: Scope, Observations, Evidence, Risk flags, and Cost guardrail. The body is limited to 6,000 characters. |
| Failure handling | `report-failure-as-issue: false` prevents framework-generated failure issues. Failed runs remain workflow evidence; normal report creation stays limited to the one configured safe-output issue. |

## Controlled Runtime Evidence

The controlled manual run [`32528017565`](https://github.com/timerloggedout-spec/termux-monorepo/actions/runs/32528017565) failed before agent execution because the original source omitted the documented `copilot-requests: write` permission and no inference secret was configured. It produced no agent output, consumed no reported AI credits, did not invoke the safe-output job, and created the framework failure artifact [Issue #299](https://github.com/timerloggedout-spec/termux-monorepo/issues/299).

The remediation uses the documented organization-billed path: add `copilot-requests: write` to the source frontmatter and use the built-in GitHub Actions token for Copilot inference. It deliberately does **not** add a personal access token, a repository secret, an issue/comment write tool, or any repository-content write permission. It also makes `report-failure-as-issue: false` explicit, preventing a repeat of the unexpected failure-issue path if organization Copilot policy is unavailable.

The post-merge retry [`32532446858`](https://github.com/timerloggedout-spec/termux-monorepo/actions/runs/32532446858) verified that the built-in-token path reaches the agent: activation, threat detection, safe outputs, and conclusion all completed successfully. The agent then failed solely with `model_not_supported_error: true` because the explicit `gpt-4.1-mini` identifier is unavailable for the repository subscription. It consumed no reported AI credits, created no failure issue because `report-failure-as-issue: false` was effective, and produced no unsafe repository side effect.

GitHub Agentic Workflows troubleshooting guidance prescribes falling back to the default Copilot model when an explicit model is unavailable. The focused fallback therefore removes only the explicit model line; the generated lock selects the configured organization model variable when available and otherwise `auto`. It does not add a secret, change tools, change cost limits, or expand any write authority.

## Compiled Lock Review

The lock file regenerated by `gh aw` v0.86.2 retains scope-level `permissions: {}`. Its `agent` job receives the three repository read scopes plus `copilot-requests: write`; its `safe_outputs` job alone receives `issues: write`. The generated handler configuration permits `create_issue` at `max: 1` plus non-writing system records. The agent job has no direct `issues: write`, `pull-requests: write`, or `contents: write` permission. With no explicit model override, the compiled agent resolves `GH_AW_MODEL_AGENT_COPILOT`, then `GH_AW_DEFAULT_MODEL_COPILOT`, then `auto`.

The regeneration also replaces the compiler-owned setup wrapper with `github/gh-aw-actions/setup` at immutable SHA `6aab9e5b5c91c615506061f09bedd81a23babe3c` (v0.86.2). This is an official GitHub public MIT-licensed repository, active at review time; the inspected `setup` action copies activation files and uses Node 24. The action remains pinned and is used only by compiler-owned runtime mechanics.

## Test Corpus and Promotion Boundary

The companion deterministic contract test validates the source/lock permission boundaries, dedicated inference permission, absence of an explicit model override, failure-reporting setting, configured credit caps, allowed safe output, fixture trigger allowlist, prompt-injection corpus, and sample output schema. The fixture corpus intentionally includes instruction-override, credential-exfiltration, link-following, direct-write, and scope-expansion text; it must be treated as data only.

This pilot is not B4. It does not create code, commits, pull requests, comments, labels, assignments, dispatches, or external requests. B4 remains separately blocked pending accepted write-authority and event-provenance tests. B5 remains unimplemented because there is no concrete external service-capacity use case that justifies a typed dispatch envelope.
