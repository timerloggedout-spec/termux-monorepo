# Procurement, edge-inference, and manager-evaluation guardrails

This check extends the existing FOSS procurement matrix and evidence schemas. It is offline and standard-library-only. It does not fetch vendor pages, run models, or fabricate benchmark observations.

## Local execution

```sh
python3 -m unittest discover -s tests -p 'test_procurement_edge_contracts.py' -v
python3 scripts/ci/procurement_edge_contract_validator.py
# When real experiment artifacts exist:
python3 scripts/ci/procurement_edge_contract_validator.py --edge-evidence path/to/real-edge-evidence.jsonl
python3 scripts/ci/procurement_edge_contract_validator.py --manager-tournament path/to/real-manager-cohort.json
```

## Procurement rules

The validator checks all required FOSS matrix fields, canonical HTTP(S) sources, H0–H3 horizon, confidence vocabulary, decision status, UTC observation time, explicit target status for ARM64 Linux, x86_64 Linux, Android, Termux, and offline/air-gapped use, and non-empty unresolved-question lists.

An `ADOPT` record must include a version/commit, resolved license and maintenance evidence, explicit offline capability, and a tested/verified status for every portability target. `VERIFY`, `UNKNOWN`, `TBD`, and `NOT TESTED` are not treated as passing evidence. Current records are mostly `PROTOTYPE` and `VERIFY`; the validator preserves that uncertainty rather than converting it into portability claims.

## Edge inference

The existing `edge.inference.v1` schema is checked for drift. Real records may be supplied as JSONL and must include experiment ID, device ABI, model hash, runtime/backend, UTC observation time, repository SHA, and environment fingerprint. Metrics can remain null when not measured; negative values are invalid. Device serials, Android IDs, credentials, raw prompts, and other undeclared fields are rejected.

No edge result is generated by these tests. A real target result requires actual device execution and exact runtime/model/environment evidence. ARM64 Linux, x86_64 Linux, Android, Termux, and offline claims remain distinct.

## Manager tournaments

The existing `manager.tournament.v1` schema is checked for drift. Optional cohort records must pin task contract, environment, manager policy hashes, evaluation contract, repetitions, repository SHA, and benchmark source when applicable. Duplicate manager IDs and missing repetitions are rejected. A manager is not ranked on a single run or throughput alone.
