# Swarms and the Termux monorepo

Kye Gomez’s Swarms is a Python multi-agent orchestration framework, not a Termux-specific runtime. Its Python version requirement is compatible in principle with modern Python, but the project does not establish Android/Termux support. Native and platform-sensitive dependencies mean an Android installation should be treated as experimental until the selected dependency set has been built and tested on the target device.

This integration adds the official Swarms repository as a **source-pinned shallow submodule** at `refTemplates/smods/swarms`, pinned to commit [`8ec7948ce6e8ab28c4454d6c2c3187a735672067`](https://github.com/kyegomez/swarms/commit/8ec7948ce6e8ab28c4454d6c2c3187a735672067). That is a reproducible source reference; it does not by itself integrate Swarms into the monorepo’s runtime, prove Termux compatibility, or imply that every user-owned repository was reviewed.

## What the primary projects declare

- **[kyegomez/swarms](https://github.com/kyegomez/swarms)** is the upstream Python orchestration project. Its [manifest](https://github.com/kyegomez/swarms/blob/master/pyproject.toml) declares package `swarms` 16.0.2, Apache-2.0, Python `>=3.10,<4.0`, and a Poetry build. Dependencies include `psutil`, `networkx`, pinned `litellm`, MCP, `zstandard`, HTTP clients, and observability packages. Python version alignment is not proof of Android support; native wheels/build requirements and individual provider integrations need checking. Model calls may need network access and provider credentials.
- **[The-Swarm-Corporation/swarms-tools](https://github.com/The-Swarm-Corporation/swarms-tools)** is a separate tools project. Its manifest declares MIT, Python `^3.10`, and dependencies including `orjson`, `lxml`, `httpx`, and MCP. Native extensions such as `orjson` and `lxml` are potential Termux build risks.
- **[The-Swarm-Corporation/swarm-models](https://github.com/The-Swarm-Corporation/swarm-models)** declares MIT and Python `^3.10`, with Transformers, Torch/Diffusers-related dependencies, LiteLLM, tokenizers and other ML packages. This is a particularly uncertain fit for on-device Termux because of native, ABI, and resource constraints. Remote inference avoids local model execution but still requires network/provider setup.
- **[The-Swarm-Corporation/swarms-memory](https://github.com/The-Swarm-Corporation/swarms-memory)** declares MIT and Python `^3.10`; its broad stack includes PyTorch, ChromaDB, sentence-transformers, FAISS, Qdrant, Pinecone and related components. Do not assume the full stack installs on Android. A smaller, explicitly selected backend may be feasible but needs its own verification.
- **[The-Swarm-Corporation/swarms-rs](https://github.com/The-Swarm-Corporation/swarms-rs)** is an Apache-2.0 Cargo workspace. Rust can target Android, but the workspace manifest does not prove this project builds in Termux; target/linker configuration and native crates need to be checked per crate.

Official adjacent repositories include [swarms-api-examples](https://github.com/The-Swarm-Corporation/swarms-api-examples), [swarms-js](https://github.com/The-Swarm-Corporation/swarms-js), [swarms-cloud](https://github.com/The-Swarm-Corporation/swarms-cloud), [swarms-core](https://github.com/The-Swarm-Corporation/swarms-core), [swarm-ecosystem](https://github.com/The-Swarm-Corporation/swarm-ecosystem), [swarms-evals](https://github.com/The-Swarm-Corporation/swarms-evals), [agents-go](https://github.com/The-Swarm-Corporation/agents-go), [Multi-Agent-Template-App](https://github.com/The-Swarm-Corporation/Multi-Agent-Template-App), and [swarms_ecosystem_md](https://github.com/The-Swarm-Corporation/swarms_ecosystem_md). These names/URLs are confirmed as profile-listed repositories, not individually audited here for implementation, releases, dependencies, or Termux support. The organization’s API examples are not evidence of a standalone locally runnable server. No `The-Swarm-Corporation/swarms` or `The-Swarm-Corporation/swarms-api` repository was found; do not conflate either guessed name with `kyegomez/swarms`.

## Practical compatibility cautions

Python `>=3.10` or `^3.10` describes an interpreter range, not working packaging on Android. Termux runs Android/Bionic rather than a conventional glibc Linux environment; binary wheels vary by Android ABI, architecture, and Python version. Native extensions, Rust/C toolchains, storage and memory, and model-provider credentials are the key compatibility concerns. Verify the dependencies actually needed, pin versions, and test in a disposable Termux environment before integrating. License identifiers above reflect project manifests; this is not legal advice.
