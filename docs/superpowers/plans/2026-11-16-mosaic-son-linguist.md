# MOSAIC SON Linguist Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Admit the MOSAIC DO-statement profile through the existing Siglary Notation Matrice and Linguist review process.

**Architecture:** Treat SON as a candidate profile over registered Siglary operators and the existing DO-statement marker. Keep the Matrice, Standard, Linguist judgment and current DO-style workflow authoritative.

**Tech Stack:** Markdown, existing Siglary Matrice, proposal lifecycle, GitHub issue and Actions evidence.

**Spec:** \`docs/superpowers/specs/2026-11-16-mosaic-meta-methodology.md\` and \`docs/proposals/active/continuous-capability-evolution-lab/MOSAIC-BRAIN-RFP.md\`.

## Global Constraints

- Preserve GLYPHS, CHORDS and OPERATORS as distinct notation classes.
- Resolve every chord inside a named Shorthand Domain.
- Use registered operators only in the candidate examples.
- Keep the existing DO-statement style workflow and its policy revisions as the enforcement path.
- Preserve accuracy over compression and use expanded language when semantics are ambiguous.
- Keep Linguist ownership of normative notation decisions.

## Review Focus

- Operator/class collision: verify the symbol and its class against the live Matrice.
- Unregistered delimiter semantics: classify colons and line breaks as grammar delimiters, not operators.
- DO marker status: verify the marker against the current policy and Linguist direction.
- Chord use: require a named Shorthand Domain and collision review.
- Stored unknowns: use schema-native nulls and keep chat-only absence markers out of records.
