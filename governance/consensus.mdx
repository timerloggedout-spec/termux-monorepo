The Termux Monorepo uses a tiered consensus system to decide when a change is safe to merge. This page explains the merit path, the CRDT model for distributed agreement, and the optional Raft-strict mode for high-stakes decisions.

## Consensus tiers

Consensus is not a single vote. It is a graduated path built on recorded debate and demonstrated merit. The tiers are documented in `docs/CONSENSUS.md`.

<Steps>
  <Step title="Propose">
    Post the idea in `docs/proposals/registry.yaml` and open debate in `DEBATE.md`.
  </Step>
  <Step title="Demonstrate">
    Show working code, test results, or impact analysis. Cite `Implements: <ITEM-ID>` on every commit.
  </Step>
  <Step title="Resolve">
    Record objections and resolutions. Consensus is reached when debate closes with no outstanding blocking concerns.
  </Step>
  <Step title="Merge">
    Only after consensus is recorded may the change proceed through the ARCHW1Z gate.
  </Step>
</Steps>

## CRDT model

The monorepo uses a Conflict-free Replicated Data Type (CRDT) model for proposal state. This means:

- Multiple agents can update proposal metadata concurrently
- Conflicts resolve automatically without a central lock
- The `registry.yaml` and `DEBATE.md` files are the source of truth

## Optional Raft-strict mode

For changes that affect gates, credentials, or core infrastructure, you can enable Raft-strict mode. This requires a quorum of maintainers to agree before the proposal advances. Use this sparingly; it is documented in `docs/CONSENSUS.md`.

## PR body rewrite rule

All PR summaries must follow the multi-agent roster format from `docs/PR-SUMMARY-PROCESS.md`. Summaries must list the agents involved and their roles. A single-agent monopoly is not acceptable.
