## Target Rung ∧ Track Pick

Target rung: **L1 FreeCodeCamp**. Track pick: **Relational Database** — over the alternative candidate, JavaScript Algorithms and Data Structures.

Both tracks (FreeCodeCamp's own curriculum descriptions): free, self-paced, ~300 hours at beginner pace, 5 required projects, verifiable certificate on completion.

| | Relational Database (PICK) | JavaScript Algorithms (deferred) |
|---|---|---|
| Covers | Bash, SQL, PostgreSQL, Git, database design/normalization | JavaScript, ES6, regex, data structures, OOP/functional algorithms |
| Projects | Celestial Bodies Database, World Cup Database, Salon Appointment Scheduler, Periodic Table Database, Number Guessing Game | Palindrome Checker, Roman Numeral Converter, Caesars Cipher, Telephone Number Validator, Cash Register |
| Evidence produced | SQL dumps ∧ Bash scripts ∧ database designs — artifacts that live naturally as public repos | Standalone algorithm exercises |

Justification, in order of weight:

1. **Gap, not duplication.** The evidence map already demonstrates JavaScript fluency extensively — the fleet's tooling and this repo's history are the proof. A JS Algorithms certificate would re-certify the best-evidenced skill on record. No equivalent evidence exists for the database layer: it is operated daily but never credentialed. L1 should close the largest evidence gap first.
2. **Role fit.** The target role's production data surface is PostgreSQL (Neon lane-events ∧ participant stores, above). Relational Database is the only L1 track that certifies the exact stack the role runs.
3. **Ladder sequencing.** L2 CTF web exploitation presupposes SQL and database structure (injection, auth data, schema reasoning). Relational Database is a direct prerequisite build for L2; JS Algorithms is not on that path.
4. **Starting-fluency match.** Bash ∧ Git — two of the track's four topics — are the operator's daily environment, so the beginner-pace estimate (~300h) overstates this track more than any other L1 option ⇒ highest completion probability, which is what a first plan should optimize for.

Disposition of the alternative: JavaScript Algorithms is **sequenced second** among L1 tracks (candidate for Plan 002), not rejected — its value rises once the database gap is closed and a second, non-duplicative evidence line is wanted.
